> [!IMPORTANT]
> QuietDo is currently **alpha software**. Source builds are intended for development and evaluation. Any preview macOS DMG is ad-hoc signed and not notarized; any preview Android APK uses a test certificate. Review the [distribution guide](docs/DISTRIBUTION.md) before redistributing a package.

## Why QuietDo?

Most todo applications store a list and leave the user to keep it clean. QuietDo focuses on the task lifecycle: capture something quickly, make the next action explicit, define what “done” means, and review work that has stalled.

The name joins two plain ideas: **quiet** software that respects attention and **doing** the next clear action. The Chinese name “轻作” conveys the same low-friction approach: make progress without turning task management into another job.

QuietDo deliberately stays smaller than an autonomous assistant:

- **Task-first:** the product opens as a task workspace, not a chat window.
- **Local-first:** task content is stored on the device and remains available offline.
- **Suggestion-first:** intelligence proposes changes; it does not silently operate other apps.
- **User-owned data:** backups use a documented JSON format and can be imported again.
- **Useful without AI:** capture, review, projects, and backup work without a model provider.

## Current capabilities

| Capability | Status | Notes |
| --- | --- | --- |
| Inbox, Today, projects, areas, smart views | Available | Shared across Web and native shells |
| Next actions and completion criteria | Available | Stored with the task |
| Offline smart capture | Available | Deterministic parsing for dates, priority, and `#project` |
| Task review | Available | Finds overdue, stale, vague, and incomplete tasks locally |
| JSON backup and restore | Available | Compatible with QuietDo and legacy Suishi/TaskFlow exports |
| PWA/offline app shell | Available | Web only; native apps do not register a Service Worker |
| AI provider and privacy controls | Configuration only | Version 0.4.0 does **not** send task content to an LLM |
| WebDAV | Configuration only | Credentials and synchronization engine are not implemented yet |
| Encrypted multi-device sync | Planned | See the [roadmap](#roadmap) |

## Platforms and downloads

When maintainers publish preview binaries, they are attached to [GitHub Releases](https://github.com/weieast1314/quietdo/releases), rather than committed to Git history.

| Platform | Minimum / target | Distribution | Status |
| --- | --- | --- | --- |
| Web / PWA | Current evergreen browsers | Self-host from `apps/web` | Supported |
| macOS | macOS 12+, Apple Silicon and Intel | Universal DMG | Preview |
| Android | Android 7.0+ (API 24), ARM64/ARMv7 | APK side-load | Preview |
| Windows | Windows 10/11 | NSIS generated by draft release workflow | Experimental, not device-tested |
| Linux | Ubuntu 22.04+/compatible distributions | DEB and AppImage generated by draft release workflow | Experimental, not device-tested |
| iOS | — | — | Planned |

For store distribution, Android requires a long-lived release keystore and AAB; macOS requires a Developer ID signature and Apple notarization. See [Distribution](docs/DISTRIBUTION.md).

### Upgrading from the Suishi preview

QuietDo 0.4.0 uses the new native identifier `com.weieast.quietdo`. It does not automatically reuse the data container created by the former preview application. Before replacing that build, export a JSON backup from its **Data** dialog, install QuietDo, and import the backup. The importer intentionally accepts both former Suishi and original TaskFlow exports.

## Quick start

### Prerequisites

- Node.js 22.13 or later and npm
- Rust stable for native builds
- Platform prerequisites required by [Tauri 2](https://v2.tauri.app/start/prerequisites/)

### Web / PWA

```bash
cd apps/web
npm ci
npm run dev
```

Open <http://localhost:3000>. Production validation:

```bash
npm run lint
npm test
```

`npm test` runs a production build, output checks, database migration checks, domain tests, and API validation tests.

### macOS desktop app

```bash
cd apps/desktop
npm ci
npm run desktop:dev
```

Build a universal Apple Silicon + Intel DMG:

```bash
rustup target add aarch64-apple-darwin x86_64-apple-darwin
npm run desktop:build:universal
```

### Android preview app

Install JDK 17+, the Android SDK/NDK, and Android Rust targets first. Then:

```bash
cd apps/desktop
npm ci
npm run android:init -- --ci
npm run android:build
```

The last command produces an optimized APK signed with the local Android test key. It is for side-loading and testing, not for Google Play. Exact prerequisites and production signing boundaries are in [Distribution](docs/DISTRIBUTION.md).

## Architecture

```text
apps/web/
├── app/             React UI and Web API routes
├── application/     Use cases and optimistic updates
├── domain/          Task model and pure domain rules
└── infrastructure/  IndexedDB, delivery queue, runtime adapters

apps/desktop/
├── src/             Tauri-specific React entry and styles
└── src-tauri/       Rust/Tauri shell for desktop and Android
```

The dependency direction is `UI → Application → Domain`. Browser and native integrations stay behind infrastructure adapters. The Tauri shell reuses the React application and domain model; it does not run a separate task backend.

### Data and privacy boundaries

- Tasks, categories, and task outbox records are authoritative in the device's IndexedDB.
- Preferences such as theme, AI scope switches, and non-secret WebDAV fields stay on the device.
- WebDAV passwords are not persisted by version 0.4.0.
- Local smart capture and review are deterministic rules and require no network request.
- Native builds do not send anonymous browser telemetry.
- A deployed Web build may send anonymous product events and user-submitted feedback to its configured D1 API; task titles and notes are excluded.

Read the Chinese [product requirements](docs/PRD.zh-CN.md) and [architecture design](docs/ARCHITECTURE.zh-CN.md) for the longer design rationale.

## Roadmap

- Encrypted, operation-based WebDAV synchronization with inspectable conflicts.
- User-controlled local or OpenAI-compatible model integration.
- Production signing, notarization, and Android AAB publishing.
- Stable Windows and Linux validation.
- iOS exploration after the sync model is stable.

The roadmap is directional, not a promise of delivery dates. Please open a [feature request](https://github.com/weieast1314/quietdo/issues/new/choose) before starting a large change.
